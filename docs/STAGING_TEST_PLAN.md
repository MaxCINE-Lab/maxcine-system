本计划用于 Cloudflare Staging 人工验收，不代表生产验收结论。测试人员应在执行时填写“实际结果”和“是否通过”，不要提前假定通过。

## 问题级别

| 级别 | 定义 |
|---|---|
| P0 | 无法登录、页面空白、核心按钮无反应、越权访问、数据写入错误、SN 丢失或重复、订单/仓库状态无法继续 |
| P1 | 布局错乱、移动端难以操作、提示不清楚、页面刷新状态丢失 |
| P2 | 轻微样式问题、非核心交互优化 |

## 建议人工测试顺序

1. 先用管理员账号验证登录、Cookie、导航、订单审核、SN 查询和售后管理。
2. 再用经销商账号创建订单并提交，确认通知和客户风控中心。
3. 回到管理员账号审核订单并准备发货信息。
4. 使用仓库账号在手机浏览器完成 SN 扫描和确认发货。
5. 使用服务中心账号验证 SN 查询只读、工单收货、检测和定损建议。
6. 最后做权限反查：每个角色直接访问不属于自己的页面和接口。

## 已知 Staging 限制

- 邮件 provider 为 Mock，不发送真实邮件。
- R2 未启用，涉及真实图片/附件上传的流程应记录为限制项。
- 浏览器首次打开后台时可能出现一次未登录的 `/api/me` 401 探测请求；登录成功后继续出现 401 才算问题。
- 本环境只允许使用虚构演示数据，不得导入真实 Excel 或真实客户资料。
